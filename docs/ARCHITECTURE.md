# Архитектура и принятые решения

## Слои

```
┌──────────────────────────────────────────────────────────────────────┐
│  Интерфейсы:  cli.py (rich)            webapp.py (Streamlit)         │
└───────────────┬────────────────────────────────┬─────────────────────┘
                │                                │
                └───────────────┬────────────────┘
                                ▼
                     runtime.py  (сборка окружения,
                     выбор режима: live / demo)
                                │
                ┌───────────────┴────────────────┐
                ▼                                ▼
        agent.py (DeepSeek)             offline_agent.py (демо)
        цикл tool calling                сценарные ответы
                │                                │
                └───────────────┬────────────────┘
                                ▼
                    tools.py — схемы + ToolExecutor
                    (валидация аргументов, ошибки → JSON)
                                │
                                ▼
              tinvest_client.py — read-only обёртка SDK
              (Quotation → float, enum → строка, TTL-кэш, retry)
                                │
                                ▼
             sdk.py — совместимость t_tech.invest / tinkoff.invest
                                │
                                ▼
                     T-Invest API (gRPC, песочница)
```

Вспомогательные модули: `config.py` (настройки из env), `logging_setup.py`
(зачистка секретов), `retry.py` (повторы), `cache.py` (TTL-кэш),
`formatting.py` (числа и проценты), `prompts.py` (системный промпт),
`demo.py` (синтетические данные).

## Ключевые решения

### 1. Какой SDK использовать
Пакет `tinkoff-investments` (импорт `tinkoff.invest`) на PyPI с марта 2025
числится как **quarantined** и больше не обновляется. Актуальный официальный
SDK — **`t-tech-investments`** (импорт `t_tech.invest`), он ставится из
реестра Т-Банка.

`sdk.py` импортирует тот пакет, который установлен, и отдаёт общий набор имён,
поэтому весь остальной код от версии SDK не зависит. Тесты вообще не требуют
SDK: сервисы подменяются моками.

### 2. Модель не видит «сырой» API
Модель не должна сама складывать `units + nano` и не должна знать, что
`roe` приходит коэффициентом. Поэтому:

* в `tinvest_client.py` все значения уже приведены к float/str;
* в `get_portfolio` посчитаны `value`, `invested`, `share_in_portfolio_pct`,
  `expected_yield_pct`;
* проценты отдаются дважды: как в API (`roe`) и в процентах (`roe_pct`).

Чем меньше арифметики на стороне LLM, тем меньше галлюцинаций в цифрах.

### 3. Нормализация процентов
T-Invest API отдаёт рентабельности и дивидендную доходность как коэффициент
(`0.241` = 24,1 %). В отдельных версиях SDK/полях встречаются уже умноженные
значения, поэтому в `formatting.normalize_percent()` используется правило:
`|value| <= 1.5` → это коэффициент, умножаем на 100. Обе формы попадают в
ответ инструмента, а системный промпт объясняет модели, какое поле чем
является.

### 4. Экономия запросов к API
* `get_portfolio` — **один** вызов: валюта позиции берётся из `MoneyValue`
  (`current_price.currency`), а не из отдельного `get_instrument_by`;
* `get_last_prices` — один батч-вызов на все бумаги;
* `get_fundamentals` — один батч `GetAssetFundamentals` на до 100 активов;
* `get_performance` — по одному вызову свечей на бумагу, результат в TTL-кэше
  (`CACHE_TTL`), поэтому повторный вопрос не «съедает» лимиты;
* карточки инструментов кэшируются в памяти по тикеру/FIGI/uid.

### 5. Ошибки как данные
`ToolExecutor` никогда не бросает исключение наружу: он возвращает
`{"error": "...", "message": "...", "hint": "..."}` и отдаёт это модели
как результат инструмента. Модель объясняет проблему пользователю
(«не нашёл тикер», «нет доступа к счёту») вместо падения приложения.

Ретраи (`retry.py`) применяются только к «шумным» ошибкам
(UNAVAILABLE, DEADLINE_EXCEEDED, RESOURCE_EXHAUSTED, INTERNAL, ABORTED и
сетевые исключения). `INVALID_ARGUMENT`/`NOT_FOUND`/`PERMISSION_DENIED`
не повторяются — это бессмысленно.

### 6. Демо-режим как подкласс
`DemoTInvestClient` наследуется от настоящего клиента и подменяет только
источники данных (счета, позиции, свечи, операции, фундаменталка). Вся
логика агрегации остаётся настоящей — поэтому демо не «врёт» про формат
ответов и заодно служит источником данных для тестов.

### 7. Логи без секретов
`logging_setup.SecretRedactingFilter` вырезает:
* точные значения токенов из настроек,
* любые строки вида `t.xxxxx` и `sk-xxxxx`,
* `Authorization: ...`, `Bearer ...`, `token=...`.

Плюс логгеры `httpx`/`openai`/`grpc` принудительно поднимаются до WARNING,
чтобы заголовки запросов не попали в DEBUG-вывод.

## Ограничения MVP

* доходность в `get_performance` — только ценовая (без дивидендов и купонов);
* живые обновления (стриминг котировок) не используются: только request/response;
* многопользовательский режим: один процесс = один набор токенов из env
  (для мультипользовательского SaaS нужен OAuth-flow Т-Инвестиций и хранилище
  сессий);
* `deepseek-reasoner` не поддерживает Function Calling, поэтому по умолчанию
  используется `deepseek-chat`.
